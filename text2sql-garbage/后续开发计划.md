## 0. 结论先行

核心对话链路（自然语言 → SQL → 校验 → 查库 → 表格/图表/Excel/CSV/图表 PNG）与**真实的会话管理**（新建/切换/删除/重命名/持久化）均已跑通。

## 3. 建议开发路线（四阶段）

### Phase 1 — 体验闭环收尾（P0，约 1 周）
**目标**：把「看得见但点不动」的占位变成真功能，先补轻量、无账号依赖的项。
- 评价回答：点赞/点踩写入审计表（复用 `lib/audit`）。文件：`ChatPanel.tsx`、新增 `app/api/feedback/route.ts`、`lib/audit` 落库。
- 收藏单条结果：`ResultPanel` 加收藏按钮 + `favorites` 本地存储（先 localStorage，与对话同机制）。文件：`ResultPanel.tsx`、`types.ts`、`page.tsx`。
- 帮助中心：静态弹层。文件：`TopBar.tsx` + 新组件 `HelpModal.tsx`。

### Phase 2 — 数据资产化（P1，约 2 周）
**目标**：让结果可沉淀、可跨端。
- 我的收藏页：从 `favorites` 渲染列表，点击跳回原会话轮次。
- 数据看板：预置 4~6 个领域 KPI 卡片（复用 chart/table）。新增 `app/api/dashboard/route.ts` 或复用 `/api/chat` 的 SQL 执行能力。
- 对话云端同步：账号体系 MVP（登录/登出）+ 后端会话表 + 同步逻辑。文件：新增 `app/api/auth`、`app/api/conversations`，`lib/db` 加表。

### Phase 3 — 平台化（P1~P2，约 2~3 周）
**目标**：多租户、多数据源、自服务。
- 数据库切换 / 数据源管理：数据源 CRUD + 连通性校验 + 运行时选源。文件：`TopBar.tsx`、`Sidebar.tsx`、新增 `app/api/datasources/*`、`lib/db` 连接池。
- 账号设置页：个人资料、密钥（API_KEY 用户侧）、偏好。
- 联网搜索（可选）：外部检索 API 接入。

### Phase 4 — 增强与运营（P2~P3，持续）
- 分享/导出整个对话（PDF/Markdown/链接）。
- 审计分析看板（质量、命中率、拒答率）。
- 查询历史独立检索视图。
- 暗色模式开关。
- 模型评估闭环：用 Phase 1 的「评价回答」数据反哺 few-shot 与提示词优化。

## 4. 优先级矩阵

| 优先级 | 功能 | 理由 |
| --- | --- | --- |
| **P0** | 评价回答、收藏单条结果、帮助中心 | 无账号依赖、成本低、立刻消除「死按钮」 |
| **P1** | 我的收藏页、数据看板、对话云端同步、数据库切换 | 决定产品是否「可用且可沉淀」，是平台化前提 |
| **P2** | 数据源管理、账号设置、分享/导出对话、审计落库、联网搜索 | 平台化与运营所需 |
| **P3** | 暗色模式、非 SELECT 只读扩展 | 体验锦上添花 / 高风险，按需 |

---

## 5. 技术债 / 备注

- `lib/audit` 的 `flush()` 目前只落内存或 console，Phase 1 做评价反馈时应一并把审计表建起来，否则反馈数据无归宿。
- `validateSQL` 强约束只读白名单；Phase 3 多数据源后，白名单需按数据源维度拆分。
- 会话目前纯前端 `localStorage`，Phase 2 云端同步要注意「本地优先 + 冲突合并」策略，避免覆盖。
- 部署门禁：Netlify Production 分支 = `main`；新功能走 `master` 开发，发布时 `git checkout main && git pull && git merge master && git push origin main`（或 `git release` 别名）。
