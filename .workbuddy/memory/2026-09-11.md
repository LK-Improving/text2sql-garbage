### ⚠️ 踩坑：React 严格模式下「mount 恢复 + state→effect 写存储」会互相污染
- **现象**：面板宽度拖到 760 后刷新回到 520，而侧栏收起状态却正常恢复。
- **根因**：挂载时 `useEffect(读 localStorage → setState)` 与 `useEffect([width] → 写 localStorage)` 同批执行。Next dev 默认 React StrictMode 会把 effect 跑两次：第一轮恢复读到的还是正确值，但写入 effect 已把**初始值 520** 写回存储；第二轮恢复读到的就是被污染的 520。侧栏状态没被污染所以正常。
- **正确做法**：布局偏好**只在事件回调里落盘**（拖拽结束 / 切换侧栏 / 双击复位），彻底删掉 `state → effect → localStorage` 这条链路；mount effect 只负责读。
- **验证方式**（可复用）：写 playwright 脚本（本机 Chrome + 全局 playwright 模块，`createRequire` 加载），流程 = 拖拽 → 读 localStorage → `page.reload()` → 断言宽度恢复 → 双击复位。注意 `browser.newContext()` 每次都是干净 profile，**localStorage 持久化必须在同一个 context 里 reload 才测得准**。
- **验收结果**：面板 520→拖拽 760→reload 仍 760→双击回 520；侧栏收起后对话区 +236px；复制 SQL 内容正确入剪贴板；CSV 内容 `total_weight,total_trips,days_count` / `61175,170,5`；饼图 5 扇区、折线图轴标签正常；全流程无 console/pageerror。
